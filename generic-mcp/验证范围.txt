Comfy Direct 全流程核实：本轮离线阶段（2026-11-09）

结论
通用工具不依赖 Codex 或 Codex CLI；旧分享说明把 Codex 专用安装流程误写成通用前提，现已纠正。
新增独立通用 MCP 安装包，Codex 插件保留为另一种安装入口。
这次完成的是安装到 MCP 调用的离线验证，不是 DeepSeek 全流程或云端生成的再次验收。

发现并修复
1. 旧包没有完整通用安装入口，导出配置仍引用 Codex 插件目录。新通用包独立安装到 ComfyDirect，输出直接调用 Node 和核心程序的配置，不依赖插件缓存。
2. 插件 Windows 启动器写死 x64 运行时路径。现按架构选择，版本更新为0.1.2；x64实测通过，ARM64仅修复逻辑，未做真机测试。
3. 离线准备可能留下未配置SSH的默认配置，导致下次跳过配置。现 -PrepareOnly 不伪造已配置状态。
4. PowerShell 5.1 默认编码使中文安装目录被读错。读取运行时JSON改为显式UTF-8，中文及空格目录实测通过。

实际验证通过
- 从测试进程PATH排除Codex和Node，全新目录下载安装便携Node24.22.2，并核对官方下载SHA256。
- 未安装/调用Codex，通用脚本独立完成配置导出；真实Codex配置哈希在通用安装测试前后不变。
- Windows PowerShell5.1及PowerShell7入口通过，包含中文和空格路径、SSH命令参数、重复安装。
- 只准备运行环境不伪造SSH配置；目标目录已有无关文件时停止并保留。
- 官方MCP SDK作为独立客户端，按导出的配置启动进程，发现7个工具。
- 本地模拟CPU服务检查成功；无GPU任务blocked_gpu，submit_attempted=false，无prompt_id，没有POST提交。
- 相同request_key返回同一任务；重启客户端后任务可查询；接口关闭时返回连接错误。
- 重新安装保留已有任务。安装目录内的连接管理入口可读任务。
- 新通用包生成核心与此前GPU验收使用的源码一致。
- 用户当前Codex插件更新为0.1.2，实际已安装插件入口读取旧验收任务成功。
- Mac Shell通过语法检查。

尚未验证，不能宣传为已通过
- DeepSeek具体Agent客户端尚未选定：未测试模型选择工具、该客户端配置界面和视频内嵌展示。
- Mac及Windows ARM64真机安装。
- 完全干净操作系统/全新服务器的部署；当前采用同一Windows主机的隔离目录和受限PATH，不冒充干净虚拟机。
- 服务器关闭期间没有重新测试SSH登录、真实上传、新生成、SeedVR2或网络中断恢复。
  之前的GPU单任务生成成功记录继续有效，但不等于新通用客户端完整验收。
